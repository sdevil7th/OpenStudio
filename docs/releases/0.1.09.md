# OpenStudio 0.1.09

This is an unpublished candidate. The
[comparison since the published 0.1.08 app](https://github.com/sdevil7th/OpenStudio/compare/v0.1.08...test-run-1-bugfixes)
and [application PR #36](https://github.com/sdevil7th/OpenStudio/pull/36)
describe the source under review. The candidate includes the shipped 0.1.08
plugin Undo and release-wrapper fixes; it does not replace them with the older
development versions. No 0.1.09 release or Store update has been published.

## Highlights

- Add a separately launched OpenStudio Support application for Windows, macOS
  and Linux. Users can collect existing diagnostic files, inspect audio/MIDI
  exports and create a support archive without installing Python or using a
  terminal. Collection and analysis require OpenStudio to be closed. Nothing
  is uploaded automatically; users review and share the resulting archive.
- Expand offline evidence with plugin scan logs, filtered plugin/audio settings,
  selected OS crash reports and exact native debug identities. Keep incident IDs
  separate from the installed version, and preserve matching native symbols and
  frontend maps outside installers at build time.
- Add audio and MIDI tempo analysis with candidate audition and Undo, editable
  linked crossfades, exact mixer level entry and a resizable single-row mixer.
- Add optional project-rate copies of imported audio while retaining original
  source files, and show conversion progress and saved MIDI-device availability.

## Fixes

- Encode OGG with the built-in Vorbis codec, preserving quality 0–10, instead of
  requiring a system FFmpeg build with the optional Vorbis encoder. Final
  sample-rate conversion retains the existing FFmpeg path. Encoding remains
  offline and cancellable, and a failed export cannot replace an existing file.
- Compile out ARA callback timing, logging arguments and per-block debug-state
  updates in ordinary builds. Remove periodic heartbeat/fault polling; flush
  failure counts at stop/shutdown. The Windows crash helper waits on events during
  normal use, while crash capture and committed-final-Quit protection remain.
- Reduce repeated work for tiny audio blocks and prepare recording storage
  before capture starts. The recording writer publishes prepared FIFO data
  without waking its disk thread from each audio callback. These changes do
  not establish a universal glitch-free minimum buffer size.
- Prepare native NAM input/track effects for the actual device block size,
  reducing unnecessary cabinet-convolution work at small buffers while keeping
  the existing preparation reserve for other effects. This adds no cabinet
  latency; the strict 8-sample contention target still fails.
- Limit timeline waveform and canvas work to the visible region, keep recording
  previews updating during navigation, and reduce ruler label crowding without
  changing the snap grid. Mixer resizing releases keyboard focus correctly.
- Preserve joined MIDI note identity, mute state and note releases; export
  selected MIDI clips consistently from the context menu and action catalog.
  Single-clip export is labelled separately. Correct selection near clip edges.
- Preserve source geometry and fades through project restoration and rendering,
  validate final project-rate conversions, and avoid conversion staging names
  that exceed Windows path limits. The fader floor produces digital silence.
- Compile callback timing histograms, stage sampling and paired trace storage
  out of ordinary builds. Missing measurements are reported as unavailable,
  including in qualification reports, rather than as zero failures. MIDI event
  placement, processing deadlines, meters and existing fault handling remain.
  Release packaging rejects an instrumented or mismatched build policy.
- Make the Windows Support window scale its text when moving between displays
  and keep its controls reachable with scrollbars on small or highly scaled
  screens. These changes run only inside the explicitly opened companion.

## Known Issues

- The strict Audient ASIO 48 kHz / 8-sample target still fails. After the NAM
  preparation/insertion correction, a four-track probe with Dota 2 running
  recorded 3,658 late callbacks out of 180,000 and also missed worker deadlines.
  The saved previous build recorded 8,948 misses in another run; game activity
  was not a controlled replay, so this is not a universal improvement claim.
  Raw synthetic-input recording integrity passed, but continuous monitoring,
  physical driver loss and subjective quality are not established. The separate
  31-track hardware gate also remains failed. Short 64-sample and FX-bypassed
  controls do not qualify the loaded 8-sample workload or long sessions.
  An explicitly approved trace found graphics-driver interruptions exceeding
  the buffer budget and paging during one late callback. These do not explain
  every miss, prove RAM exhaustion or establish a past unobserved glitch's cause.
  On 5 November the user accepted this as a non-blocking known limitation for
  merging PR #36. The measured failure is retained; no glitch-free eight-sample
  claim or relaxed test threshold follows from that decision.
- Offline support cannot reconstruct unmeasured CPU scheduling or RAM pressure
  at a past glitch, prove that every intended instrument was audible, or replace
  a physical signal reference. Redaction is best effort; inspect archives before
  sharing. Crash dumps are optional and can contain private information.
- Full Windows installer/MSIX packaging and installed-app checks passed; Linux
  DEB installation and AppImage qualification passed. These are unpublished test
  artifacts. Final Windows browser checks passed. The rebuilt MSIX passed
  Windows App Certification Kit overall and all 13 required tests, including
  the corrected Support DPI check; two optional findings remain in its report.
  All four final Linux browser-test groups passed: 295 cases, 33 declared skips,
  zero failures and zero retries. Microsoft Store approval remains
  outstanding. A subsequently available Apple Silicon runner built the app and
  reached frontend readiness in main/popout windows, but three window-geometry
  checks failed; full DMG qualification did not complete. Native and universal
  Support component checks passed on both architectures. Apple signing/
  notarization credentials are unavailable. Component passes do not certify
  the full candidate. See the
  [candidate qualification record](../certification-0.1.09.md).
  Windows/Linux packages and WACK were requalified after the native NAM
  preparation/insertion change at `bba16515`. A subsequent warning-only preview
  initializer correction at `b6aba8ae` has passed Windows/Linux qualification
  and its separate WACK check. Results apply to the exact
  artifacts recorded in the qualification report.
- Automated render and MIDI checks establish objective behavior for their test
  inputs. They do not establish subjective sound quality or compatibility with
  every external plugin, interface or driver.

## Upgrade Notes

- These further support/diagnostic changes are source changes after `93d03c15`.
  Earlier installer/WACK/Linux certification results do not qualify these new
  binaries. Automatic timed dumps for running-session UI hangs are disabled in
  ordinary builds; explicitly selected OS evidence or a diagnostic reproduction
  is needed for those cases. No publication or new certification is claimed.
- Back up projects before opening them in this candidate. Existing project
  files remain supported; save a separate copy when testing new editing flows.
  The 0.1.08 plugin Undo corrections remain included.
- Open Support explicitly from the installed shortcut or launcher after closing
  the DAW. No support process, scheduled collector or service needs to run during
  recording. Close Support before reopening OpenStudio.
- Keep existing audio interfaces and driver settings for comparison. Use the
  buffer/workload combination qualified on your hardware; a successful export
  or a larger-buffer test does not qualify an eight-sample recording session.
